# pi-quiet-mode

**为 [Pi](https://pi.dev) 打造的三级安静模式。** 把工具噪音挪开，又不至于看不见它在干什么。

[English](README.md) | **中文**

Pi 默认的转录会把每次工具调用、每个结果，以及每个被隐藏思考块的 `Thinking...` 标签都显示出来。调试时很好用，平时很吵。本扩展增加一个 `/quiet` 开关，分三档。

## 档位

| 档位 | 命令 | 转录显示 | 适合场景 |
|------|------|----------|----------|
| **1 完全安静** | `/quiet 1` | 一个实时的 `Thinking...` 指示，然后是最终结果。没有工具行、没有中间解说、没有空行填充。 | 只想下达指令、看结果。 |
| **2 部分安静** | `/quiet 2` | 每步一句话解说（在做什么 / 发现了什么 / 下一步），最后是最终结果。工具细节仍然隐藏。 | 想看着 agent 干活，又不想被输出刷屏。 |
| **3 关闭** | `/quiet 3` | Pi 原生行为。 | 调试、审计、完全透明。 |

`/quiet` 不带参数循环 `关闭 → 1 → 2 → 关闭`。当前档位显示在状态栏（`quiet:1` / `quiet:2`），重启后保持。

安静档位下 **`Ctrl+O` 循环切换工具可见性**：隐藏 → 最近若干轮用户提问的工具 → 全部工具 → 隐藏。`/quiet recent N`（1–20，默认 1）设置"最近"包含多少个用户轮次；状态栏显示 `tools:recent×N`。

## 安装

```bash
# 从 npm（发布后）
pi install npm:pi-quiet-mode

# 直接从 git
pi install git:github.com/LvGitHub-9/pi-quiet-mode

# 本地开发目录
pi install /path/to/pi-quiet-mode
```

或者不安装直接试用：

```bash
pi -e /path/to/pi-quiet-mode/extensions/quiet-mode.ts
```

无需任何配置。启动 Pi 后运行 `/quiet`。

## 各档位具体行为

**档位 1（完全安静）**
- 工具调用与输出不渲染任何行——没有东西需要滚过去。
- 中间解说被隐藏；只显示本轮运行的最后一个回答。
- 隐藏的思考标签及其残留的"仅 ANSI"空行会被移除，不留空行。
- 工具失败仍会保留**一行红字**，失败绝不会被静默吞掉。
- 编辑器边框上的实时 `Thinking...` 指示继续显示"正在工作中"。

**档位 2（部分安静）**
- 工具调用与输出的隐藏方式与档位 1 相同。
- 保留助手的解说。会向系统提示注入一条指令，要求模型在**每次工具调用前恰好写一句简短说明**。
- 失败同样保留一行红字。

**档位 3（关闭）**
- 重新注册原始定义，Pi 内置的工具渲染、思考标签、间距原样恢复。

## 附加特性

- **`Ctrl+O`**：Pi 的保留快捷键，扩展无法注册它。安静档位通过终端输入监听接管该键，循环 **隐藏 → recent → 全部 → 隐藏**。"recent" 覆盖最近 `N` 个用户轮次里的全部工具调用（`/quiet recent N`）。档位 3 保持 Pi 原生的展开/收起全部行为。
- **`Ctrl+T`** 仍然切换思考块的显示。安静档位下，偷看只作用于当前会话，因此 reload 后旧历史会重新渲染干净。
- **持久化**：档位与"最近轮次数"存于 `<agent-dir>/quiet-mode.json`（默认 `~/.pi/agent/quiet-mode.json`）。
- **无行为漂移**：扩展重建内置工具定义时，会复刻会话使用的全部选项——包括 `shellPath`、`shellCommandPrefix`、`autoResizeImages`——所以你的设置照常生效。它只覆盖仍为 `builtin` 的工具；被其他扩展替换过的工具绝不触碰。
- **容错的内部补丁**：Pi 的消息组件总会插入间隔行，并为隐藏的思考标签留下"仅 ANSI"的一行，这两者都无法通过公开扩展 API 移除。扩展自带一个小的、受保护的补丁（用 `Symbol.for` 标记，仅在安静档位激活时生效）来过滤这些行。如果 Pi 内部结构变化，补丁会静默失效，一切仍正常渲染。

## 已知限制

- 工具输出只是被隐藏，并未删除。`Ctrl+O`（或 `/quiet 3`）总能把它找回来。
- 工具返回的内联图片仍由 Pi 自己的组件层显示。
- 档位 2 的解说质量取决于模型是否遵循"一句话"指令。
- 扩展覆盖内置工具 `read`、`bash`、`edit`、`write`、`find`、`grep`、`ls`。自定义工具保持各自的渲染。
